# Changes — 20260727

Railway (Linux Docker) + Azure SQL deployment preparation for the .NET 8 backend, with DevAuth
(header/bypass auth) enabled for all users during testing.

`.cs` changes carry an inline `// Change 20260727` marker. JSON and new infrastructure files are
logged here instead.

## `backend/src/InnovationToImpact.Api/appsettings.Production.json`

- `ConnectionStrings:InnovationDb` — was a `REPLACE_WITH_SQL_SERVER\INSTANCE` /
  `Trusted_Connection=True` placeholder. Now an **empty string**: the real value is supplied at
  runtime through the `ConnectionStrings__InnovationDb` environment variable so no Azure SQL
  credential is committed. Expected value on Railway:

  ```
  Server=tcp:i2i-testing-raid.database.windows.net,1433;Initial Catalog=InnovationToImpact;Persist Security Info=False;User ID=admin-i2i;Password=<SQL_PASSWORD>;MultipleActiveResultSets=False;Encrypt=True;TrustServerCertificate=False;Connection Timeout=30;
  ```

- **Added `DevAuth` section** — `AlwaysOn: true` and `SamAccountName: "devuser"`. `AlwaysOn` keeps the
  `X-Dev-User` header scheme (and the fake AD directory) active in the Production environment;
  `devuser` is the account used when a request carries no header, and the dev-users seeder grants it
  every role (Innovator, Evaluator, Committee/Judge, Supervisor, Admin). Override with
  `DevAuth__AlwaysOn=false` to restore Negotiate/LDAP.

- **Storage root paths** — `ReportStorage`, `EvidenceStorage`, `TemplateStorage`, `HomeMediaStorage`
  and `EmailTemplateAttachmentStorage` moved from `C:\InnovationToImpact\storage\*` to
  `/app/storage/*`. The Windows paths are meaningless inside the Linux container. Railway's
  filesystem is ephemeral, so mount a volume at `/app/storage` to keep uploads across redeploys.

- `ActiveDirectory` and `Smtp` placeholders left untouched — unused while `DevAuth:AlwaysOn` is true.

## `Dockerfile` (new, repo root)

Multi-stage `mcr.microsoft.com/dotnet/sdk:8.0` → `mcr.microsoft.com/dotnet/aspnet:8.0`. Listens on
`http://+:8080`, exposes 8080, entrypoint `dotnet InnovationToImpact.Api.dll`.

Two deliberate decisions:

- It builds `backend/src/InnovationToImpact.Api/InnovationToImpact.Api.csproj`, **not**
  `backend/InnovationToImpact.sln`. The solution still lists `InnovationToImpact.Infrastructure.Tests`
  and `InnovationToImpact.Api.Tests`, but `backend/tests/` does not exist in this repo, so a
  solution-level restore fails. Building the API project transitively covers Domain and
  Infrastructure — i.e. all source that exists.
- The runtime stage installs `libfontconfig1` and `fonts-dejavu-core`; QuestPDF report rendering
  needs native font libraries that the `aspnet` image does not ship.

## `railway.json` (new, repo root)

`builder: DOCKERFILE`, `dockerfilePath: Dockerfile`, health check on `/api/health/db` (300 s timeout,
which covers an Azure SQL serverless resume), restart `ON_FAILURE` with 3 retries.

## `.dockerignore` (new, repo root)

Excludes `frontend/`, `bin/`, `obj/`, `node_modules/`, `.git/` and `scripts/` from the build context.

## Deployment checklist

1. Railway variable `ConnectionStrings__InnovationDb` = the Azure SQL connection string above.
2. Azure SQL firewall: allow Railway's outbound IPs (or "Allow Azure services" if applicable).
3. Optional: Railway volume mounted at `/app/storage`.
4. First boot applies all EF migrations and seeds roles, the idea template, homepage sections and the
   dev users. Expect a slow first start.
5. Frontend calls from `https://i2i-tawny.vercel.app` (and `*.vercel.app` previews) are allowed by
   CORS with credentials; send `X-Dev-User: <samAccountName>` to act as a specific user, or omit it to
   act as `devuser` with all roles.
