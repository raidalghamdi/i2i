## Backend contract mismatches (no backend was modified)
The brief's field list does not match the deployed API. Where they disagree, the API won:

- **No `description` field exists.** `IdeaInput` carries three prose pairs
  (`problemStatement*`, `proposedSolution*`, `expectedBenefits*`). The single Description
  per language maps to `problemStatement*`; the other four are sent blank by
  `toIdeaInput()` in `ideas.service.ts`.
- **`POST /api/ideas` requires more than these screens collect** — `activityId` (a
  non-nullable Guid) plus `ipAcknowledged`/`termsAgreed`, which the endpoint rejects with
  `ConsentRequired`. Save as Draft is therefore expected to return **400 against the real
  backend** until those are collected. The error surfaces in the red banner as designed.
- **Attachments are multipart, not JSON metadata.** `POST /api/ideas/:id/attachments`
  binds an `IFormFile`, so `addAttachment` sends `FormData`. The new-idea screen keeps the
  picked `File` objects and uploads them after the draft is created, because
  `POST /api/ideas/:id/submit` rejects an idea with **zero attachments**.
- **No combined create-and-submit endpoint**, so Submit chains
  `POST /api/ideas` → attachment uploads → `POST /api/ideas/:id/submit`.
- **Withdraw is limited to `draft`, `submitted`, `returned`** (`IdeaService.WithdrawableStatuses`).
  The button is disabled outside those states so it cannot generate a 400.
