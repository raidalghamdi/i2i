# Change 20260726 — Phase 4a: backend gap closure

Backend only; no frontend files touched, no npm packages added.

## Notification preferences
- `NotificationPreference` entity + `NotificationPreferences` table, UNIQUE index on
  `(UserId, CategoryKey)`. A missing row means the category is un-muted, so no backfill
  is needed for existing users.
- `NotificationCategories` holds the static bilingual category catalog.
- Mute enforcement lives inside `NotificationService.CreateAndPublishAsync`, so every
  existing and future trigger site inherits it without per-call-site changes.

## Notification triggers
Four new triggers, all routed through `INotificationService.CreateAndPublishAsync` (the real
seam — there is no `NotifyAsync`). Because that method is per-user, every audience wider than
one recipient fans out through `CreateAndPublishToUsersAsync` / `CreateAndPublishToRolesAsync`.

- `idea_submitted` — admins + the evaluators assigned to the idea's theme, on submit and resubmit.
- `evaluation_completed` — supervisors + admins, once evaluation quorum is reached.
- `committee_decision_made` — submitter + admins, per judge decision.
- `idea_status_changed` — submitter, on every transition. Transitions live in eight services, so
  this goes through `IIdeaStatusNotifier` to keep the wording and audience identical everywhere.

`CreateAndPublishAsync` now returns `Notification?`; `null` means the recipient muted the category.

## Evaluator productivity
`GET /api/reports/evaluator-productivity` (AdminOnly). Turnaround is measured from the assignment
that produced the evaluation, not the idea's age.
